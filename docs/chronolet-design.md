# КОЛИЗИУМ — дизайн-документ

> Рабочее название. Кооперативная 2.5D-игра в браузере (three.js) о путешествии во времени по истории науки.
> Хакатон: 2 дня, всё работает локально в LAN, без интернета.

---

## 1. Концепция в одном абзаце

Экипаж маленького космического корабля-Колизиума застрял в прошлом: **хроно-двигатель сломан** и может прыгать только недалеко по времени. Чтобы двигаться дальше, в каждой эпохе нужно добыть **деталь для двигателя**. Детали выдают за выполнение заданий исторических персонажей — а задания это образовательные головоломки (доказать гелиоцентризм вместе с Галилеем, взломать Энигму вместе с Тьюрингом и т. д.). **Головоломки решаются только вдвоём**: один игрок видит данные, другой управляет механизмом. Остальные игроки помогают, мешают или бегают вокруг. Сквозной **бортовой ИИ** корабля язвительно комментирует происходящее и подсказывает.

**Визуальный стиль:** 2.5D side-scroller в духе «рукодельных» платформеров — картон, ткань, дерево, нитки, мягкий тёплый свет, несколько слоёв глубины. Свой герой и свой стиль, без заимствований чужих персонажей.

---

## 2. Ключевые правила дизайна

1. **Это НЕ одиночная игра.** Ни одну головоломку нельзя решить в одиночку.
2. **Каждая головоломка рассчитана ровно на двоих** с асимметричными ролями:
   - **Наблюдатель** — видит данные, но не может на них влиять;
   - **Механик** — управляет механизмом, но не видит данных.
   Им приходится общаться (голосом за столом или через внутриигровой чат).
3. **Роли** занимают первые двое, кто встал на платформы ролей у головоломки. В следующей эпохе роли предпочтительно отдаются тем, кто ещё не играл.
4. **Остальные игроки — «свободные руки»:** могут помогать (носить предметы, держать, бегать с сообщениями), мешать (утаскивать предметы, толкать, загораживать) или просто не понимать, что происходит. Головоломки должны оставаться решаемыми, даже если им мешают, но мешать должно быть весело.
5. **Деталь выдаёт игровая логика**, а не LLM. Проверка решения детерминированная. Уговорить персонажа «просто отдать деталь» нельзя.
6. **ИИ отвечает за слова, а не за правила:** рассказчики эпох, комментарии бортового ИИ, подсказки.

## 3. Структура игры

```
[Логин] → [Хаб: корабль] → Эпоха 1 → Хаб → Эпоха 2 → Хаб → ... → Эпоха 5 → Финал
```

- **Хаб — корабль.** Мастерская: хроно-двигатель в центре с 5 гнёздами под детали, табло прогресса, рычаг прыжка. Прыжок возможен, когда все игроки на борту и деталь текущей эпохи получена.
- **Эпоха** — горизонтальный уровень с несколькими слоями глубины: стартовая зона, рассказчик, головоломка (с платформами ролей), декорации.

## 4. Головоломки

### 4.1 Эратосфен — «Тень и колодец» (облегчённая, обучение)

- Уровень разделён на два города: **Сиена** и **Александрия**.
- **Наблюдатель (Сиена):** в полдень видит, что солнце освещает дно колодца — тени нет. Знает расстояние между городами (5000 стадий).
- **Механик (Александрия):** двигает измерительную дугу у обелиска и видит угол тени (~7,2°).
- **Решение:** понять, что 7,2° = 1/50 круга → окружность Земли = 5000 × 50 = 250 000 стадий. Ввести ответ в «счёты» (Механик), подтвердить (Наблюдатель).
- **Свободные руки:** могут перетаскивать зеркальца, отвлекающие внимание.
- **Проверка:** угол в допуске ±0,3°, ответ в допуске ±5%.

### 4.2 Галилей — «Фазы Венеры» (полная)

- **Наблюдатель (крыша, телескоп):** видит Венеру и Юпитер в окуляре. Не видит модель.
- **Механик (мастерская):** армиллярная модель — двигает Солнце, Землю, Венеру по орбитам, переключает схему «Земля в центре» / «Солнце в центре».
- **Ход:** 3 «ночи» наблюдений. В каждую ночь Наблюдатель описывает фазу Венеры («полный диск», «половина», «тонкий серп»), Механик выставляет модель так, чтобы она давала ту же фазу. В геоцентрической схеме полный диск получить **невозможно** — игроки сами приходят к выводу.
- **Бонусный шаг (если успеем):** спутники Юпитера — тела, которые вращаются не вокруг Земли.
- **Свободные руки:** держат лампу-«Солнце», разгоняют облака (или нагоняют), могут сбить наводку телескопа.
- **Проверка:** модель в гелиоцентрической схеме + 3 фазы совпали с наблюдениями.

### 4.3 Ньютон — «Пушка Ньютона» (облегчённая)

- Пушка на вершине горы маленькой планеты-шарика.
- **Механик:** задаёт скорость ядра рычагом.
- **Наблюдатель:** на другой стороне планеты видит, где упало ядро, говорит «больше/меньше».
- **Решение:** найти скорость, при которой ядро выходит на орбиту и возвращается к пушке.
- **Проверка:** скорость в коридоре орбитальной.

### 4.4 Тьюринг — «Энигма» (полная)

- **Наблюдатель (радиорубка):** видит перехваченное шифрованное сообщение и знает «подсказку» (crib): утренний прогноз погоды всегда содержит слово `WETTERBERICHT`.
- **Механик (машина-«бомба»):** крутит 3 ротора, видит, во что шифруется каждая буква при текущих настройках.
- **Шаг 1 — найти позицию crib.** Главная слабость Энигмы: **буква никогда не шифруется сама в себя**. Наблюдатель двигает слово вдоль шифровки и отбрасывает позиции, где хотя бы одна буква совпадает. Остаётся 1–2 позиции.
- **Шаг 2 — подобрать роторы.** Наблюдатель диктует пары «шифр → открытый текст», Механик подбирает положения роторов, пока пары не совпадут.
- **Шаг 3:** сообщение расшифровано полностью → деталь.
- **Свободные руки:** носят перфоленты между комнатами, бегают с донесениями (или путают их).
- **Упрощение для хакатона:** упрощённая Энигма (3 ротора без коммутационной панели), алфавит 26 букв, количество допустимых настроек ограничено.
- **Проверка:** положения роторов совпадают с ключом.

### 4.5 Королёв — «Ступени» (полная, финал)

- **Наблюдатель (бункер управления):** знает формулу Циолковского `Δv = v_e · ln(m0 / m1)`, характеристики двигателей, видит симуляцию полёта и требуемую скорость (~7,9 км/с).
- **Механик (монтажный цех):** собирает ракету из ступеней и баков, буквально перетаскивая детали по уровню. Видит массы деталей.
- **Ход:** одноступенчатая ракета не долетает — на симуляции видно, где она падает. Игроки сами понимают, зачем нужны ступени.
- **Свободные руки:** таскают баки, заправляют, мешают сборке.
- **Финал:** запуск → деталь → хроно-двигатель починен → прыжок домой → титры.
- **Проверка:** суммарная Δv ≥ 7,9 км/с, масса в пределах грузоподъёмности стартового стола.

## 5. ИИ-персонажи

### 5.1 Рассказчики эпох

| Персонаж | Характер | Не знает |
|---|---|---|
| Эратосфен | спокойный учитель, любит вопросы | ничего после III в. до н. э. |
| Галилей | вспыльчивый, ироничный, обижен на церковь | Ньютона, Энигму, ракеты |
| Ньютон | педантичный, нелюдимый, ревнивый к чужим открытиям | всё после 1700 |
| Тьюринг | застенчивый, точный, шутит сухо | ракеты, полёт Гагарина |
| Королёв | жёсткий, деловой, торопит | всё после 1961 |

Что делают:
- вводят в эпоху и объясняют задачу;
- отвечают на вопросы игроков в рамках своих знаний (на анахронизмы реагируют удивлением);
- **помнят, что уже говорили конкретному игроку**, и не повторяются;
- **ссылаются на пройденные эпохи** («Грек мерил Землю тенью? Мы с тобой сделаем похожее, но с небом»);
- при ошибках объясняют **другим способом**, а не повторяют то же самое.

### 5.2 Бортовой ИИ корабля

Сквозной персонаж через все эпохи. Вежливо-ядовитый, саркастичный (по настроению в духе GLaDOS, но свой характер и имя — рабочее: **ХРОНОС**).

- **Комментирует события:** падения, ошибки, простой, кто что утащил, кто помогает, кто мешает.
- **Подсказки по нарастающей:**
  1. намёк («Может, стоит посмотреть на Венеру внимательнее?»);
  2. направление («Обрати внимание: в схеме с Землёй в центре Венера никогда не бывает за Солнцем»);
  3. почти ответ.
  Уровень растёт по числу неудачных попыток и времени без прогресса.
- **Помнит историю экипажа** между эпохами («В Падуе вы справились быстрее. Деградируете?»).

### 5.3 Как устроен агент (офлайн)

Каждый агент = **файл личности** + **карточки знаний** + **память в БД** + **LLM**.

```
agents/
  galileo/
    persona.md        # характер, манера речи, эпоха, запреты (анахронизмы)
    knowledge.json    # карточки тем: {id, title, text, tags}
    fallback.json     # заготовленные реплики по состояниям головоломки
  ship_ai/
    persona.md
    events.json       # шаблоны комментариев на события (фолбэк)
    hints/<epoch>.json # подсказки 3 уровней
```

**Сборка промпта на каждую реплику:**
1. `persona.md`;
2. текущее состояние головоломки (этап, число попыток, роли);
3. 2–3 релевантные карточки знаний (простой поиск по тегам/ключевым словам, без векторной БД);
4. **сводка памяти об игроке:** какие карточки уже рассказаны, с какими агентами говорил, какие ошибки делал;
5. вопрос или событие.

После ответа — записать в память, какие карточки использованы.

**Фолбэк:** если LLM не ответила за ~3 с, берём реплику из `fallback.json` / `events.json`. Игра не должна ждать LLM.

**Бортовой ИИ и частота комментариев:** события идут в очередь с приоритетами, не чаще 1 комментария в 8–10 с, важные события (решение, деталь, прыжок) — вне очереди. Короткие ответы (1–2 предложения).

## 6. Стек (предложение)

| Слой | Технология | Зачем |
|---|---|---|
| Язык | TypeScript везде | общие типы сообщений для клиента и сервера |
| Клиент | three.js + Vite | 2.5D-рендер, быстрая сборка |
| Физика клиента | своя простая 2D-физика платформера (AABB) или Rapier | для платформера хватит своей |
| Сервер | Node.js + Fastify | HTTP: логин, раздача клиента, API |
| Реалтайм | `ws` (WebSocket) | двунаправленный обмен после авторизации |
| Авторизация | логин/пароль → JWT, токен передаётся при подключении к WS | WS работает только после авторизации |
| БД | SQLite (better-sqlite3 или Prisma) | один файл, ноль настройки |
| LLM | Ollama на сервере, модель 7–8B instruct с хорошим русским | рассказчики и бортовой ИИ |
| Запуск | `npm run start` на машине-сервере, клиенты открывают `http://<ip>:3000` | ничего не ставить на клиентах |

### Авторитарность
- **Движение игроков:** клиент считает своё движение сам и шлёт позицию ~15–20 раз/с; сервер рассылает остальным; клиенты интерполируют чужих игроков.
- **Головоломки, предметы, роли, детали:** только сервер. Клиент шлёт намерения («взять предмет», «повернуть ротор»), сервер меняет состояние и рассылает всем.

## 7. Архитектура

```
[Браузер: three.js]  ──HTTP (логин, статика)──▶  [Node: Fastify]
        ▲  │                                          │
        │  └──── WebSocket (JWT) ────────────────▶  [GameServer]
        └──────── события, состояние ─────────────     ├─ SessionManager (экипаж, текущая эпоха)
                                                       ├─ PlayerSync (позиции, анимации)
                                                       ├─ PuzzleEngine (FSM головоломок)
                                                       ├─ ObjectSystem (предметы, захват)
                                                       ├─ EventBus ──▶ AgentService
                                                       │                 ├─ Narrator (рассказчики)
                                                       │                 ├─ ShipAI (комментарии, подсказки)
                                                       │                 └─ Ollama (localhost:11434)
                                                       └─ DB (SQLite)
```

### Протокол WebSocket (черновик)

**Клиент → сервер**
| type | payload |
|---|---|
| `move` | `{x, y, z, vx, vy, anim, facing}` |
| `grab` / `release` | `{objectId}` |
| `role.take` / `role.leave` | `{puzzleId, role}` |
| `puzzle.action` | `{puzzleId, action, value}` |
| `chat.say` | `{text}` |
| `agent.ask` | `{agentId, text}` |
| `jump.request` | `{}` |

**Сервер → клиент**
| type | payload |
|---|---|
| `welcome` | `{playerId, session, epoch, players[], objects[], puzzle}` |
| `players.update` | `[{id, x, y, z, anim, facing}]` (пакетно, 15–20 Гц) |
| `player.join` / `player.leave` | `{id, name}` |
| `object.update` | `{objectId, x, y, z, heldBy}` |
| `puzzle.state` | `{puzzleId, stage, roles, publicState, privateState}` — **privateState только своей роли** |
| `agent.say` | `{agentId, text, to?}` (можно стримить частями) |
| `ship.comment` | `{text, about?}` |
| `hint` | `{level, text}` |
| `part.awarded` | `{epoch, part}` |
| `epoch.change` | `{epoch}` |

> Важно: **данные Наблюдателя не отправляются Механику и наоборот.** Иначе асимметрия ломается через DevTools.

### Головоломка как конечный автомат

```ts
interface Puzzle {
  id: string;
  stage: string;                    // 'waiting_roles' | 'observe_1' | ... | 'solved'
  roles: { observer?: string; mechanic?: string };
  attempts: number;
  lastProgressAt: number;
  onAction(playerId: string, action: string, value: unknown): PuzzleEvent[];
  viewFor(playerId: string): { public: unknown; private: unknown };
}
```

`PuzzleEvent` (`attempt_failed`, `stage_passed`, `solved`, `idle`) уходят в `EventBus` → бортовой ИИ и рассказчик.

## 8. Модель данных (SQLite)

```sql
players (
  id TEXT PRIMARY KEY, name TEXT UNIQUE, password_hash TEXT,
  created_at INTEGER
);

sessions (
  id TEXT PRIMARY KEY, current_epoch INTEGER, parts_json TEXT,  -- полученные детали
  started_at INTEGER, finished_at INTEGER
);

player_state (
  player_id TEXT, session_id TEXT,
  epoch INTEGER, x REAL, y REAL, z REAL,
  roles_played_json TEXT,           -- сколько раз был наблюдателем/механиком
  PRIMARY KEY (player_id, session_id)
);

agent_memory (
  agent_id TEXT, player_id TEXT,
  told_cards_json TEXT,             -- id рассказанных карточек
  mistakes_json TEXT,               -- типичные ошибки игрока
  last_summary TEXT,                -- короткая сводка для промпта
  updated_at INTEGER,
  PRIMARY KEY (agent_id, player_id)
);

events_log (
  id INTEGER PRIMARY KEY, session_id TEXT, player_id TEXT,
  type TEXT, payload_json TEXT, ts INTEGER
);

dialog_log (
  id INTEGER PRIMARY KEY, agent_id TEXT, player_id TEXT,
  role TEXT, text TEXT, ts INTEGER
);
```

Сохранение позиций — раз в несколько секунд и при выходе, не на каждый `move`.

| Вечер | Полировка визуала и звука, экран «память агентов» для жюри, прогон на всех ноутбуках в LAN, репетиция демо. |

### Приоритеты (что резать первым)
1. **Обязательно:** логин + WS, синхронизация игроков, хаб, Галилей, Энигма, рассказчики с памятью, бортовой ИИ с подсказками, сохранение в БД.
2. **Важно:** Королёв, Эратосфен, Ньютон, перенос предметов «свободными руками».
3. **Если останется время:** стриминг ответов LLM, экран памяти агентов, анимации прыжка, звук, спутники Юпитера.

## 11. Сценарий демо (5–7 минут)

1. Экипаж в хабе. Бортовой ИИ язвительно представляется и объясняет поломку.
2. Прыжок в Падую. Галилей рассказывает о споре с церковью. Двое занимают роли.
3. Третий игрок утаскивает линзу — бортовой ИИ комментирует.
4. Механик ошибается дважды → подсказка → Галилей объясняет по-другому, чем в первый раз.
5. Решение → деталь → прыжок. Следующий рассказчик ссылается на пройденное.
6. Экран для жюри: память агентов в БД — что каждый персонаж знает о каждом игроке.

## 13. Риски

| Риск | Что делаем |
|---|---|
| LLM отвечает медленно при нескольких игроках | короткие ответы, очередь запросов, стриминг, фолбэк-реплики через 3 с |
| LLM выдумывает факты | карточки знаний в промпте, запрет выходить за них в `persona.md` |
| Игроки пытаются «уговорить» агента отдать деталь | деталь выдаёт только `PuzzleEngine` |
| Рассинхрон предметов | предметы и головоломки только на сервере |
| Асимметрию ломают через DevTools | приватные данные роли не отправляются другим |
| Не успеваем | порядок резки из раздела 10 |
