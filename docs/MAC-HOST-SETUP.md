# Мак-хост «Колизиума»: автофикс сетевого экрана (pf)

Для коллеги с таким же рабочим маком. ZeroTier-сеть команды — в
[docs/ZEROTIER-SETUP.md](docs/ZEROTIER-SETUP.md); этот документ — про вторую
половину проблемы, специфичную для наших рабочих маков.

## В чём проблема

На маках с корпоративным security-ПО в **pf** (межсетевой экран ядра) загружена
политика «блокировать всё входящее»:

- пинги и DNS проходят, **входящий TCP молча дропается** — страницы игры и
  WebSocket не грузятся;
- `curl` с самого мака работает (self-трафик не режется) — проблема маскируется;
- лечение (pass-правило для подсетей команды) **runtime-only**: security-ПО
  перезагружает pf, и правило слетает — на хакатоне это случалось по несколько
  раз в день.

Симптом знакомый: «страница загрузилась, но не заходит» или «коллеги не могут
подключиться», хотя сервер и ZeroTier живы.

## Установка (один раз, ~1 минута)

Склонируй репозиторий и выполни **одну команду**:

```bash
cd <путь к hackathon>
sudo bash scripts/mac-net.sh --install-daemon
```

Что произойдёт:

1. добавит `pass in quick inet from <подсеть> to any` для каждой текущей
   подсети команды — ZeroTier (`zt*`/`feth*`), раздача интернета (`bridge100+`),
   Wi-Fi/Ethernet (`en*`/`eth*`); VPN/Docker не трогает;
2. поставит **LaunchDaemon** `com.chronolet.mac-net` — он проверяет и чинит
   правило при загрузке системы и раз в 30 секунд (переживает слёты
   security-ПО и перезагрузку мака);
3. пароль спросят один раз.

После этого сетевой конфиг чинится сам — перед каждым запуском сервера (`npm
start`, `npm run dev`, `npm run up`) правило уже на месте.

## Проверка

```bash
sudo bash scripts/mac-net.sh --status    # pf, подсети, правила, демон
bash scripts/mac-net.sh --print-subnets  # без root: какие подсети детектятся
tail /var/log/com.chronolet.mac-net.log  # что чинил демон (пишет только изменения)
```

Финальная проверка — с чужого ноутбука в ZeroTier-сети открыть
`https://<твой-zt-ip>:2567` (сертификат самоподписанный → «Дополнительно →
Перейти»; IP подскажет `curl -sk https://localhost:2567/api/host` — ZT-адрес
должен быть первым).

## Откат

```bash
sudo bash scripts/mac-net.sh --remove-daemon   # убрать автоприменение
```

pf-правила при этом остаются (они безвредны). Убрать руками:
`sudo pfctl -a main -s rules` → удалить строки `pass in quick inet from
<подсеть> to any` → загрузить файл обратно `sudo pfctl -a main -f <файл>`.

## Частые вопросы

**На маке нет корпоративного security-ПО — навредит ли скрипт?**
Нет: если pf выключен (дефолт macOS), скрипт сообщает «фикс не нужен» и
выходит; правил не пишет.

**Правило снова слетело?**
Не может — демон чинит его каждые 30 с (максимальное окно простоя — 30 с).
Проверь `tail /var/log/com.chronolet.mac-net.log`.

**ZeroTier-интерфейса нет в списке подсетей.**
ZeroTier 1.16+ на macOS поднимает `feth*`, а не `zt0` — скрипт знает оба
имени. Если подсети пусты — ZeroTier-клиент не запущен или сеть не подключена
(см. ZEROTIER-SETUP.md).

**Windows/Linux-коллегам нужно это?**
Нет — это только про pf на macOS-хосте.

## Как это работает (для любопытных)

Скрипт читает текущий набор pf-правил (тот же anchor, где сидит block-политика
security-ПО — `anchor "main"`; если его нет, корневой набор), дописывает только
недостающие pass-правила и перезагружает набор — **чужие правила не
затираются**. Idempotent: повторный запуск ничего не меняет. Подсети
вычисляются из живых интерфейсов на каждом запуске — смена адреса ZeroTier
подхватится сама в течение 30 с.
