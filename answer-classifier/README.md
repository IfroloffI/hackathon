# answer-classifier — вопросы-ворота NPC

У входа на каждый уровень NPC задаёт вопрос с **многими** верными ответами. Верен ли ответ, решает
не LLM, а бинарный классификатор: по логрегу на bag of words на каждого из 5 NPC.

| npc_id | NPC | Вопрос (суть) | Верно | Неверно |
|---|---|---|---|---|
| `eratosthenes` | Эратосфен | любой учёный или философ Древней Греции | Архимед, Евклид, Гипатия… | Ньютон, Цезарь, Зевс |
| `galileo` | Галилей | любое моё открытие или изобретение | спутники Юпитера, фазы Венеры, маятник… | тяготение, теория относительности |
| `newton` | Ньютон | любой цвет, на который призма разложила свет | красный … фиолетовый, индиго | белый, розовый, коричневый |
| `turing` | Тьюринг | любая машина, которая умеет вычислять | компьютер, счёты, Бомба, Энигма… | холодильник, печатная машинка |
| `korolev` | Королёв | любой космонавт или астронавт | Гагарин, Терешкова, Армстронг… | Королёв, Циолковский, Лайка |

Тексты вопросов и ответов NPC — в [questions.json](questions.json) (единый источник: игровой сервер берёт их через `GET /npcs`).

## Как устроено

- **Датасеты** — `data/<npc_id>.csv` (`text,label,entity`), по 300 ответов, 70% верных / 30% неверных.
  Синтезированы `generate_datasets.py` (seed фиксирован): списки верных и неверных сущностей
  + немного свободных ответов вручную, подставленных в разговорные шаблоны («Например, …»,
  «я думаю это …»), часть — с опечатками и без заглавных. Неверные — неверные сущности и
  мусор/отговорки («не знаю», «открой ворота»). Каждая сущность есть в данных хотя бы раз.
- **Признаки** (`features.py`): нижний регистр, ё→е, стемминг Snowball («Архимеда» = «Архимед»),
  без слов-связок («ну», «наверное», «я думаю»), униграммы + биграммы, бинарные.
- **Модель**: `LogisticRegression(class_weight="balanced")` — 70/30 не превращается в «пропускать по умолчанию».
- **В сервисе** перед векторизацией незнакомое слово исправляется на ближайшее из словаря модели
  (Левенштейн-Дамерау ≤ 1, для длинных слов ≤ 2: «архимет» → архимед, «компутер» → компьютер).
  Нет ни одного знакомого слова → ответ неверный, модель не вызывается.
- Модели обучаются **при сборке образа** (`RUN python train.py`) — образ всегда в sync с `data/`.

## Качество (`python train.py`, тот же путь, что в сервисе)

| NPC | accuracy (5-fold CV) | F1 | ложно пропущено / 90 | ложно отказано / 210 | accuracy на невиданных сущностях |
|---|---|---|---|---|---|
| eratosthenes | 0.963 | 0.974 | 4 | 7 | 0.63 |
| galileo | 0.967 | 0.976 | 2 | 8 | 0.70 |
| newton | 0.990 | 0.993 | 0 | 3 | 0.87 |
| turing | 0.990 | 0.993 | 1 | 2 | 0.62 |
| korolev | 0.980 | 0.986 | 3 | 3 | 0.58 |

«Невиданные сущности» — GroupKFold по сущностям: модель не видела ни одного примера с этим именем.
Bag of words такое имя не знает, и почти всегда **отказывает** (а не пропускает) — ворота ошибаются
в безопасную сторону. Отсюда главный рычаг качества: полнота списков в `generate_datasets.py`.
Игрок назвал верный ответ, а его не пустили — добавьте сущность в список `pos` и пересоберите.

## API

```
GET  /health
GET  /npcs                         вопросы, реплики да/нет и метрики по каждому NPC
POST /classify {npc_id, text}      → {npc_id, accepted, probability, known_words}
```

```bash
curl -s -X POST http://127.0.0.1:8780/classify -H 'Content-Type: application/json' \
  -d '{"npc_id":"korolev","text":"ну, Юрий Гагарин"}'
# {"npc_id":"korolev","accepted":true,"probability":0.962,"known_words":["юр","гагарин","юр гагарин"]}
```

Неизвестный `npc_id` → 404. Порог — `ACCEPT_THRESHOLD` (0.5).

## Запуск

```bash
docker compose up -d answer-classifier                                                   # macOS
docker compose -f docker-compose.yml -f docker-compose.linux.yml up -d answer-classifier # Linux
```

Сервис на `127.0.0.1:8780`; игровой сервер ходит туда сам (`ANSWER_CLASSIFIER_URL`,
`ANSWER_CLASSIFIER_ENABLED=0` — выключить).

## В игре: ворота у входа в каждую эпоху

- Справа от NPC стоят ворота (`Level.gate` в `shared/src/level.ts`) — твёрдые, пока закрыты: клиентская
  физика считает их стеной, сервер не пускает за них при проверке движения.
- Через ~3.5 с после прилёта NPC сам задаёт вопрос всем; E у NPC — повторить вопрос.
- Пока ворота закрыты, **каждое сообщение в чат** — ответ (можно и `@Эратосфен Архимед`):
  классификатор решает, NPC всей комнате отвечает «Да! …» / «Нет. …».
- Верный ответ — ворота открываются для всех (`state.gatesOpen`), створка сворачивается вверх, сценарий
  переходит от шага «Ворота» к брифингу. Дальше чат обычный, `@NPC` — вопрос рассказчику, как раньше.
- События: `gate.answer` (`agentId, text, accepted, probability`), `gate.open`.
- Сервис недоступен — ворота остаются закрытыми (открывает только верный ответ), игроки видят сообщение «судья недоступен». `ANSWER_CLASSIFIER_ENABLED=0` — ворот нет.

Проверка всего пути (бот: прыжок → вопрос → ворота держат → «Нет» → «Да» → проход):
`npm run gate -w server` (с HTTPS-сервером: `NODE_TLS_REJECT_UNAUTHORIZED=0 SERVER_URL=https://127.0.0.1:2567 npm run gate -w server`).
