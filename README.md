# Хронолёт

Кооперативная 2.5D-игра в браузере. Дизайн — [docs/chronolet-design.md](docs/chronolet-design.md), архитектура — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

**Один хост:** всё (сайт, WebSocket, БД, позже LLM) крутится на одной машине. Остальные ноутбуки в LAN только открывают браузер.

## Требования

- Node.js ≥ 22.13 (в `package.json` закреплён через Volta; без Volta — `nvm use 22`).
- Больше ничего: SQLite встроен в Node (`node:sqlite`), нативных сборок нет.

## Запуск

```bash
npm install

# Разработка: сервер :2567 (tsx watch) + Vite :5173 с HMR
npm run dev
# → http://localhost:5173, с других ноутбуков http://<ip-хоста>:5173

# «Боевой» режим на хакатоне: один процесс, один порт
npm run build && npm start
# → http://<ip-хоста>:2567
```

Проверки:

```bash
npm test                          # юнит-тесты: физика (shared) и головоломки (server)
npm run smoke -w server           # мультиплеер: комнаты, синхронизация, БД (сервер запущен)
npm run playthrough -w server     # два бота проходят все 5 эпох до финала (сервер запущен)
```

В `npm run dev` включён `CHRONOLET_SOLO=1`: один игрок может занять обе роли — удобно тестировать в одиночку. В `npm start` (хакатон) головоломки строго на двоих.

## Что уже есть

- Лобби: имя, создание комнаты (4-символьный код), вход по коду или из списка открытых комнат, ссылка-приглашение `/?room=CODE`.
- Кнопка «Скопировать приглашение» в игре: ссылка всегда с LAN-IP хоста (даже если хост открыл игру как localhost) — её можно сразу кидать в чат.
- Комната-экипаж на Colyseus: до 6 игроков, синхронизация движения (клиент шлёт 20 Гц, сервер проверяет скорость/границы и рассылает патчи 20 Гц), интерполяция чужих игроков, чат, переподключение (20 с).
- SQLite: игроки, сессии, позиции (пачкой раз в 5 с и при выходе; при перезаходе в ту же комнату игрок появляется там же), журнал событий. Таблицы под память агентов уже созданы.
- three.js: 2.5D-сцены, твёрдая 3D AABB-физика платформера (бег, прыжки, глубина W/S).
- **Игровой цикл:** борт хронолёта → рычаг прыжка → эпоха → головоломка на двоих → деталь → «все на борт» у приземлившегося хронолёта → деталь загорается в двигателе → следующая эпоха → после 5 деталей финал.
- **Пять эпох и головоломок** (chronolet_ideas.docx), у каждой роли свой экран и свои данные:
  | Эпоха | Наблюдатель видит | Механик управляет | Деталь |
  |---|---|---|---|
  | Сиена и Александрия | расстояние, «тени нет» | дугой гномона (видит тень) | Гномон |
  | Падуя, 1610 | фазу Венеры в телескопе | моделью: схема, положение Венеры | Линза |
  | Англия, 1687 | мишень и траектории | скоростью и углом пушки | Маятник |
  | Блетчли-парк, 1941 | перехват и WETTERBERICHT | тремя роторами (видит таблицы) | Ротор |
  | Байконур, 1961 | формулу, телеметрию | ступенями ракеты (видит массы) | Топливный элемент |
- Роли занимаются клавишей E у светящихся кругов; рассказчики эпох и бортовой ИИ ХРОНОС говорят заготовленными репликами и помнят, что уже рассказали игроку (`agent_memory`); подсказки ХРОНОСа растут с числом ошибок (намёк → направление → почти ответ).

## Переменные окружения (server)

| Переменная | По умолчанию | |
|---|---|---|
| `PORT` | `2567` | порт единственного хоста |
| `HOST` | `0.0.0.0` | слушать на всех интерфейсах (LAN) |
| `DB_PATH` | `data/chronolet.db` | файл SQLite |
| `OLLAMA_ENABLED` | — | `1`, чтобы включить LLM (пока заглушка) |
| `OLLAMA_URL` / `OLLAMA_MODEL` | `http://127.0.0.1:11434` / `qwen2.5:7b-instruct` | |
| `DEBUG_EVENTS` | — | `1` — логировать события шины |
| `CHRONOLET_SOLO` | — | `1` — один игрок может держать обе роли (в `npm run dev` включено) |

Отладочные эндпоинты: `GET /api/host` (LAN-адреса хоста), `GET /api/rooms`, `GET /api/sessions`, `GET /api/sessions/:code` (позиции игроков из БД).
